# Prisma 7 (Postgres, NestJS)

Приоритет у правил репозитория (`CLAUDE.md`). Для актуального API сверяйся с документацией (context7, если установлен): Prisma 7 заметно отличается от 5/6 (конфиг в `prisma.config.ts`, driver adapters, генерация клиента в `src/prisma/generated/`).

## Структура проекта

- Схема: `apps/api/src/prisma/schema.prisma`. Конфиг: `src/prisma/prisma.config.ts`.
- Клиент в `src/prisma/generated/` генерируется командой `pnpm --filter api prisma:generate`, руками не править.
- Доступ к БД только через `*.repository.ts` и `PrismaService`. Контроллеры и сервисы Prisma напрямую не вызывают.

## Миграции

1. Правишь `schema.prisma`.
2. `prisma migrate dev --name <описательное_имя>` создаёт и применяет миграцию локально.
3. `pnpm --filter api prisma:generate`.
4. Уже применённые миграции не редактируй. Ошибку исправляй новой миграцией.
5. `migrate reset`, `db push --force-reset`, удаление данных и таблиц только после подтверждения пользователя.
6. На проде только `prisma migrate deploy`, никогда `migrate dev`.

### Безопасные изменения на живой таблице

- Новая колонка NOT NULL: сначала nullable или с `@default`, backfill, потом ограничение (отдельными миграциями).
- Переименование и удаление колонки: в несколько релизов (добавить новое, перейти, удалить старое). Prisma по умолчанию делает drop + create и теряет данные: проверяй сгенерированный SQL до применения.
- Индексы на больших таблицах: `CREATE INDEX CONCURRENTLY` вручную правится в SQL миграции.
- Всегда читай `migration.sql` перед коммитом.

## Схема

- Индексы на поля фильтрации, сортировки и внешние ключи (`@@index`), уникальность через `@@unique`.
- Явно задавай `onDelete` для связей.
- Деньги: `Decimal` или целые минимальные единицы, не `Float`.
- Время: `DateTime` в UTC, `createdAt @default(now())`, `updatedAt @updatedAt`.
- Enum и маппинг имён (`@map`, `@@map`) в едином стиле с существующей схемой.

## Запросы

- Выбирай только нужное: `select` вместо выгрузки всей модели; не отдавай наружу поля вроде `passwordHash`.
- N+1: используй `include` / `select` с вложением или один `findMany` с `where: { id: { in } }`, не цикл запросов.
- Пагинация: `take` / `skip` или курсор (`cursor`) с детерминированной сортировкой.
- Многошаговые изменения в `$transaction`; внутри интерактивной транзакции не делай внешних вызовов (HTTP, очереди).
- Конкурентные обновления: атомарные операции (`increment`), `upsert` по уникальному ключу, ловля `P2002` (unique) и `P2025` (не найдено) и перевод в понятные HTTP-ошибки в сервисе.
- Raw SQL только через `$queryRaw` с шаблонными параметрами, не `$queryRawUnsafe` с пользовательским вводом.

## Тесты

- Unit-тесты сервисов: мокай repository, не Prisma.
- Интеграционные: отдельная тестовая БД, не dev-данные пользователя.
