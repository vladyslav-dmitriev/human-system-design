# Шаблоны

## Тест-кейс
```
ID: TC-<область>-<номер>
Название: <действие и ожидание в одной строке>
Приоритет: P0–P3          Тип: smoke | функциональный | негативный | регрессия
Предусловия: <данные, роль, состояние>
Шаги:
  1. ...
  2. ...
Ожидаемый результат: <наблюдаемый, проверяемый факт>
Автоматизировать: да | нет (причина)
```

## Тест-план (кратко)
- Область и цель, что вне объёма.
- Риски и допущения.
- Стратегия: уровни (unit / API / e2e / ручные), браузеры, локали, данные.
- Критерии входа и выхода (все P0/P1 пройдены, нет открытых Critical).
- Результаты: сводная таблица pass / fail / blocked / skipped.

## Smoke перед релизом
- Регистрация и вход, выход.
- Главный пользовательский сценарий.
- Оплата тестовой картой, отображение подписки.
- Смена настроек профиля.
- Переключение локали.
- Страницы без 5xx и ошибок в консоли.

## Регрессия
Берётся из карты рисков: области, которые затрагивает diff, плюс критичные потоки (auth, billing). Кейсы, которые падали раньше, всегда включаются.

## Чек-лист формы
Обязательные поля, подсказки об ошибках на нужном языке, фокус на первое ошибочное поле, disabled при отправке, сообщение об успехе, сохранение введённого при ошибке, автозаполнение браузера, вставка из буфера, Enter для отправки.
