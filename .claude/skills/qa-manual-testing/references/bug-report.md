# Баг-репорт

```
Заголовок: <где> + <что не так> (без «не работает»)
Окружение: URL / ветка / коммит, браузер и версия, устройство, локаль, роль
Severity: ...    Priority: ...
Шаги воспроизведения:
  1. ...
Ожидаемый результат: ...
Фактический результат: ...
Воспроизводимость: всегда | N из M | плавающий (условия)
Доказательства: вывод теста, скриншот или видео, лог консоли, HAR, ответ API (с вырезанными токенами)
Предполагаемое место: файл или эндпоинт, если понятно
Кому: frontend | backend | devops
```

Правила:
- Один баг на репорт. Минимизируй шаги до самого короткого воспроизведения.
- Отдели факт от гипотезы. Гипотезу помечай как предположение.
- Перед отправкой проверь, что баг не дубликат и воспроизводится на чистом состоянии.
- Токены, cookie, персональные данные в репорт не попадают.
