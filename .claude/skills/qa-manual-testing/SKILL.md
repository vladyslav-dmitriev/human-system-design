# Ручное тестирование (senior QA)

Цель: найти риски до пользователей. Сначала риск и ценность, потом объём проверок.

## Процесс

1. **Понять изменение**: `git diff main...HEAD`, описание задачи, критерии приёмки. Если критериев нет, сформулируй их сам и явно перечисли допущения.
2. **Оценить риск**: что сломается при ошибке (деньги, авторизация, данные, i18n). Чем выше риск, тем глубже проверка. Рядом ищи регрессию в связанных модулях.
3. **Тест-дизайн**: применяй техники из `references/test-design.md`, не придумывай кейсы «на глаз».
4. **Выполнение**: сначала smoke (фича вообще работает), затем позитивные сценарии, негативные, граничные, затем exploratory.
5. **Отчёт**: результаты по кейсам, баги по шаблону, остаточные риски, что не проверено и почему.

## Что покрывать всегда

- Happy path и основные альтернативные пути.
- Валидация: пустые значения, пробелы, длинные строки, юникод и эмодзи, спецсимволы, HTML/SQL-подобный ввод.
- Границы: min, max, min−1, max+1, ноль, отрицательные.
- Права: гость, пользователь, чужие данные (IDOR), истёкший токен.
- Повторные действия: двойной клик, повторная отправка, back/refresh, два вкладки одновременно.
- Состояния UI: loading, empty, error, offline, медленная сеть.
- i18n: все локали проекта, длинные тексты, формат дат и чисел, отсутствующие ключи.
- Адаптив: mobile 375, tablet 768, desktop 1440. Клавиатура и фокус, базовая a11y (метки, контраст, aria).
- Браузеры: Chrome, Safari, Firefox как минимум для критичных потоков.
- Платежи (Stripe): только тестовые карты, сценарии decline, 3DS, повторный вебхук.

## Exploratory-сессия

Тайм-бокс 30–60 минут, чартер вида «Исследовать <область> с помощью <приёмов>, чтобы найти <риски>». Веди заметки: что проверил, что удивило, вопросы, баги. Эвристики: SFDIPOT, CRUD, «что если пользователь делает наоборот», тур по данным и состояниям.

## Приоритет и серьёзность

- **Severity** (влияние): Blocker, Critical, Major, Minor, Trivial.
- **Priority** (срочность): P0–P3. Не путай: опечатка в логотипе может быть P0 при Trivial severity.

## Инструменты

Для ручной проверки в браузере используй playwright MCP или встроенный браузер. Для API: `curl` против локального стенда или Swagger. Данные только тестовые, никаких реальных аккаунтов и карт, секреты не вставлять в отчёт.
