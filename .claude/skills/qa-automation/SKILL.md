# Автоматизация тестирования (senior QA / SDET)

Общий контекст и команды в `CLAUDE.md`. Продуктовый код не менять: баги описывать в отчёте.

## Пирамида и выбор уровня

- **Unit** (быстро, много): чистая логика, валидация, сервисы. web: `pnpm --filter web test:run` (vitest). api: `pnpm --filter api test` (jest).
- **API / интеграция**: контроллеры + реальная БД или тестовый контейнер, supertest. Проверять коды, схему ответа, ошибки валидации, авторизацию.
- **E2E** (медленно, мало): только критичные пользовательские потоки. Всё, что можно проверить ниже по пирамиде, на e2e не выноси.

Решай по риску: поток с деньгами и авторизацией покрывается на нескольких уровнях, косметика не автоматизируется.

## Playwright в этом репо

- Тесты: `packages/e2e/tests/*.spec.ts`, page objects: `packages/e2e/pages`, конфиг: `packages/e2e/playwright.config.ts`.
- Проекты: `setup` (логин, сохраняет `playwright/.auth/user.json`), `no-auth`, `authenticated`. Новый spec добавь в `testMatch` нужного проекта.
- Запуск: `pnpm test:e2e` (собирает web, baseURL `http://myapp.local`). Один файл: `pnpm --filter e2e exec playwright test tests/<file>.spec.ts`, отладка: `--ui` или `--debug`, трасса: `npx playwright show-trace`.
- Подробные правила и шаблоны: `references/playwright.md`.

## Золотые правила

1. **Селекторы**: `getByRole`, `getByLabel`, `getByText`, затем `data-testid`. Никаких CSS/XPath-цепочек и индексов `nth`, если можно иначе.
2. **Ожидания**: только auto-waiting и web-first assertions (`await expect(locator).toBeVisible()`). Никаких `waitForTimeout` и `sleep`.
3. **Независимость**: тест сам готовит данные и не зависит от порядка. Уникальные данные через генератор (`crypto.randomUUID()`), не общие аккаунты для мутирующих тестов.
4. **Один тест, одна проверяемая идея**, понятное имя «что делает → что ожидается».
5. **Page Object**: действия и локаторы внутри, ассерты в тесте. Без логики ветвления внутри page object.
6. **Данные**: только тестовые. Stripe только тестовые карты. Секреты из env, не в коде и не в логах.
7. **Моки сети** (`page.route`) для недетерминированного и внешнего (почта, сторонние API), но основной поток проверяй против реального backend.
8. **Не маскируй баг**: падение из-за продукта не лечится `retry` или `skip`. Оформи баг и пометь `test.fixme` со ссылкой на него.

## Flaky-тесты

Порядок разбора: воспроизвести (`--repeat-each=20`, `--workers=1` и `--workers=4`), посмотреть trace и video, найти причину (гонка, общие данные, анимация, неявное ожидание, порядок), исправить причину, не симптом. Карантин только временный и с владельцем. Подробнее: `references/playwright.md`.

## Что сдавать

- Тест проходит локально минимум 3 раза подряд, а при смене логики падает (проверь, что тест вообще ловит баг: временно сломай условие).
- `typecheck` и `lint` зелёные для затронутого пакета.
- Отчёт: добавленные и изменённые тесты, результат прогона, найденные баги, пробелы покрытия.
