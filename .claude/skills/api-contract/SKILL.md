# Контракт web ↔ api

Источник истины: Swagger-декораторы и DTO в `apps/api` (подключение в `apps/api/src/setup-swagger.ts`). Клиентские URL собраны в `apps/web/api.ts` (`NEXT_PUBLIC_API_CLIENT_URL` для браузера, `NEXT_PUBLIC_API_SERVER_URL` для серверных компонентов). Типов клиента из OpenAPI нет, типы ответов пишутся вручную.

## Как описывать эндпоинт в отчёте

```
POST /todos            (auth: cookie JWT, роль: любая)
Request:  multipart/form-data { title: string (1..200), file?: png|jpg|webp ≤5MB }
Response 201: { id, title, completed, createdAt, imageUrl|null }
Ошибки:   400 валидация | 401 нет сессии | 403 чужой ресурс | 404 не найдено
Что нужно от frontend: добавить API_URL.todos.create() в apps/web/api.ts, форма + i18n-ключи
Что проверить qa: happy path, пустой title, файл >5MB, чужой todoId
```

## Правила

- Меняешь контракт: обнови и api, и `apps/web/api.ts` в одном изменении, либо явно перечисли, что осталось другой стороне.
- Обратная совместимость: не удаляй и не переименовывай поля ответа, которые использует web, пока web не обновлён.
- Ответ описывай через Response DTO с `@ApiProperty` (не прямой Prisma-объект), чтобы Swagger совпадал с реальностью и не утекали лишние поля.

## Как менять эндпоинт

1. Опиши контракт до кода (формат выше): метод, путь, query/body, ответ, коды ошибок, кто имеет доступ.
2. API: DTO запроса и ответа классами с `@ApiProperty`, на методе `@ApiOperation` и `@Api*Response` для каждого кода (200/201, 400, 401, 403, 404, 409).
3. Web: функция URL в `apps/web/api.ts` в нужной группе, тип ответа рядом с использованием.
4. Ломающее изменение (переименование, удаление поля, смена типа) делай в три шага: API поддерживает оба варианта, затем web, затем удаление старого. Добавление необязательных полей безопасно.
5. Сверь схему с живым Swagger.

## Чек-лист ревью

- Каждый новый эндпоинт имеет Swagger-описание и guard.
- Есть запись в `apps/web/api.ts` или явная пометка, что фронт не обновлён.
- Коды ошибок обработаны на фронте (форма показывает 400/409, 401 ведёт на логин).
- В ответе нет секретов, хешей паролей и ненужных клиенту внутренних id.
- Типы ответов на клиенте сверены с Response DTO вручную (`reviewer` это проверяет). Улучшение на будущее: генерация типов из OpenAPI (`openapi-typescript`).
